# 构图与运镜设计笔记

> 2026-11-16 与 agent 讨论后的整理，记录构图系统的核心概念、横竖屏适配策略与
> 入场运镜（camera move）的设计决策。代码事实以源码为准：`lib/composition.js`、
> `lib/spine/SpineStage.jsx`、`features/viewer/components/CompositionPanel.jsx`。

## 1. 设计画布是什么

设计画布是一块**虚拟画布**，不是真实屏幕。背景图（`<img>`）和 Spine 模型
（canvas）两层都画在同一块画布里，用统一的「设计像素」描述位置和大小。

- **画布大小来自背景图的原生像素**：`resolveDesign()` 优先读背景 PNG 的
  IHDR 宽高，读不到时兜底 `FALLBACK_DESIGN`（2048×2048）。skel 里的
  `width/height` 只是 setup 包围盒，不是画布。
- **整块画布再映射到屏幕**：`designScale()` 按视口和 `fit` 模式算等比缩放
  ——`contain` 完整显示（可能留黑边），`cover` 铺满裁切（可能裁边）。

类比：设计画布是美术的「原画框」。按原画坐标摆好背景和角色，整张原画一起
投影到任何屏幕，画里的东西互相之间**永远不错位**。构图数值只允许设计坐标
单位（纯数字 = 设计像素，`'10%'` = 画布百分比），`resolveLayerTransform()`
是唯一解析点。

## 2. 横竖屏兼顾策略

**问题**：横屏画布（1920×1080）+ `contain` 在竖屏上会缩成一条横带居中，
上下全是 letterbox——「竖屏显示为中间一小段横屏」。

**结论方案**：方形画布 + `fit: 'cover'` + 主体居中。

- 方形画布下，两个方向的 cover 都只保留中央约 56% 的带（竖屏裁左右、
  横屏裁上下），谁也不吃亏，对称裁切。
- 人物主体（脸 + 躯干）落在画布中央 56% 带内；四肢出带被裁可接受。
- 背景 scale 要保证裁切窗口内不露边。
- 入场每段逐段检查：切到单段循环预览，确认每段主体都在可视范围内。
- 视差幅度别太大，漂移太猛会把主体推出裁切窗口。

**画布尺寸选择**：

| 背景 | 建议 |
| --- | --- |
| 背景是方图 | `design: null`（跟随背景），1:1 采样最清晰 |
| 背景非方形 | 固定 `2048×2048`（2 的幂、GPU 友好、余量够） |
| 背景原生 ≥2560 | 可用 2560×2560，2K/4K 竖屏余量更足 |
| 背景只有 ~2048 | 别硬上 2560，画布比图大 = 强行上采样变糊 |

注意：画布改大后 `model.heightRatio` 相对 `design.height` 计算，人物会等比
缩小，需要把 zoom/层缩放按比例补回。

构图面板已支持：「方形·跟随背景」（取背景较长边）、`2048×2048` 预设、
自定义宽高输入（64–8192，只填一轴时另一轴默认同值成方形）。方形是默认值
（配置文件显式写了 `design` 或手动选过则不再覆盖）。

## 3. 调试页辅助工具（/spine-viewer）

- **视口切换**：比例 × 方向两组按钮（16:9 / 21:9 / 16:10 / 4:3 / 1:1 ×
  横屏 / 竖屏），预览框按所选比例信箱式居中。竖屏 = 比例取倒数。
- **交叉区域开关**：在画布上标出「当前比例 ↔ 倒数比例」cover 裁切后都可见
  的中央交叠区（红虚线框）。方形画布 + 16:9 时即中央 9/16 正方形——把主体
  调进这个框，横竖屏都成立。
- 背景选择下拉单独一行，摆在视口选项下方。

## 4. 入场运镜（camera move，已实现）

### 4.1 配置格式

`wallpaper.config.json` 的 `entrance.clips` 每段可加：

```json
"cut_A": {
  "backdrop": "...",
  "backdropTransform": { "scale": 1.2, "offsetX": 0, "offsetY": 0 },
  "modelTransform": { "...": "..." },
  "camera": {
    "from": { "zoom": 1,    "x": 0,    "y": 0 },
    "to":   { "zoom": 1.15, "x": "5%", "y": 0 },
    "duration": 4,
    "ease": "easeOut"
  }
}
```

语义（用户拍板的决策）：

- **`from`、`to` 同时存在才播**，缺任一个 = 画面静止（残缺配置是静止帧，
  不是半程动画）；字段缺省即 1 / 0 / 0。
- `x` / `y` 是相对**画面中心**的平移，设计像素或画布百分比字符串。
- `duration` 秒，`0` = 跟随该段动画时长；运镜在段内按 duration **循环**
  （循环点会瞬间跳回起点——这是设计使然，想要平滑就让 duration 接近段长）。
- `ease`：`linear` / `easeIn` / `easeOut` / `easeInOut`，默认 linear。

### 4.2 实现要点

- **镜头作用在整个设计画布上**（背景 + 人物一起动），在「画布 → 屏幕」映射
  层实现：`designScale` 结果乘 zoom、加平移。两层共享一个映射，构图不变量
  （相对位置恒定）零破坏。
- 纯函数 `resolveCamera` / `cameraAt` 在 `lib/composition.js`，可纯 Node 复算。
- `SpineStage` 新增 `onSequenceFrame(clip, elapsed)`，每帧回报当前段和段内
  秒数（跟 speed 联动）；壁纸页与调试页把姿态**直接写**进设计元素的
  transform，60fps 无 React state。
- **transform-origin 是 0 0（左上角）**，zoom 必须补偿中心漂移
  `(1 - zoom) × 画布边 / 2`，否则推近时画面歪滑、看着卡——驱动里已处理。
- `.wallpaper-design` / `.compose-design` 加 `will-change: transform` 提升
  合成层；无相机段跳过冗余 style 写入。

### 4.3 编辑 UI

构图面板「入场（按段）」每段有「运镜」区：添加/移除、起点/终点各一组
（缩放 + 水平/垂直偏移，以画布百分比显示）、时长、缓动下拉。
「复制完整配置」会把 camera 一起写出。
（曾修复：滑块 onChange 只回传单字段导致互相重置，改为合并进原 pose。）

## 5. 段间镜头衔接（方案 B，未实现，纯调参手法）

段间过渡是 cross-fade（`blend` 秒）。若**上一段的 `camera.to` 数值抄成
下一段的 `camera.from`**，渐变窗口里旧镜头滑到终点、新镜头从同一点出发，
看起来就是一次不间断的运镜（PV 一镜到底感）；故意错开则产生跳切冲击。

不需要任何新代码，纯手工抄数值。可选的小增强：每段运镜区加一个
「起点 ← 上段终点」按钮，一键抄值。

## 6. 明确不做的（方案 C）

Spine 真 3D 相机：背景是 2D 图片，只有模型层有 3D 相机会让两层运动脱节，
破坏构图不变量，工作量大收益低。想要伪深度可后续给 camera 加可选
`depth`（人物层跟随镜头比例 >100%），暂不做。
